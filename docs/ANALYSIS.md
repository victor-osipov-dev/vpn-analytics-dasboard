# NetScope: как приложение локализует обрывы соединения

Документ описывает, какие проверки и выводы реализованы в ядре и как их читать.
Приложение не утверждает, что ошибка вызвана конкретным регулятором: оно
показывает технические признаки, альтернативные объяснения и уровень уверенности.

## 1. Уровни измерений

| Слой | Что сохраняется | Где смотреть |
| --- | --- | --- |
| DNS | rcode, A/AAAA, тайминг, ответ контрольного DoH, `mismatch` | «Диагностика» → dns, карточка проверки |
| TCP | connected/refused/reset/timeout/unreachable, локальный адрес, интерфейс | карточка проверки |
| TLS | версия, шифр, SAN, **TLS alert**, `clientHelloSent`, `failureStage` | карточка проверки |
| HTTP | код, **класс** (ok/redirect/client_error/server_error/block_page), server, content-type, cf-ray, IP ответившего узла, цепочка редиректов | карточка проверки |
| Производительность | RTT, jitter, доля неудачных коннектов, пропускная способность | «История», «Скорость» |
| Маршрут | интерфейс, gateway, DNS, egress IP, ASN | «Маршруты» |

Каждое измерение связано с сохранённым `network_context` (снимок интерфейсов,
маршрутов, прокси и DNS на момент проверки).

## 2. Анализатор

`netscope-analyzer` подключён к планировщику: после каждой проверки строятся
диагнозы по паре DIRECT/VPN с использованием окна последних 40 измерений.

Правила:

- для вывода «фильтрация» требуется **несколько повторов** (настраивается через
  `min_samples_for_filtering`); один неудачный замер даёт только низкую уверенность;
- деградация определяется относительно **скользящей медианы** успешных замеров;
- каждый диагноз содержит признаки и альтернативные объяснения;
- одинаковые выводы дедуплицируются на 10 минут;
- при подтверждённой фильтрации создаётся инцидент `BlockedSuspected`, а при
  восстановлении он закрывается;
- если включено `deepDiagnosticsOnAnomaly`, автоматически запускается глубокая
  диагностика (не чаще одного раза в 5 минут на пару цель/маршрут).

Категории: DNS-фильтрация, IP-блокировка, TCP RST, TLS/SNI-фильтрация,
HTTP-фильтрация, частичная доступность, ограничение QUIC, PMTU black hole,
устойчивая деградация, локальная проблема, сбой сервиса, проблема VPN.

## 3. Глубокая диагностика

Доступна на странице «Диагностика» и запускается автоматически при аномалии.
Последовательность проверок (каждая с контрольным измерением):

1. **DNS** — системный резолвер против контрольного DoH; расхождение → DNS-фильтрация.
2. **TCP** — цель против заведомо доступного `1.1.1.1:443`; если цель не отвечает,
   а контроль работает → IP-блокировка или TCP RST.
3. **TLS/SNI** — два рукопожатия к одному IP: с целевым SNI и с контрольным
   (`example.com`). Если целевой SNI не проходит, а контрольный проходит →
   фильтрация по SNI. Сертификаты для этого теста не проверяются намеренно:
   важен сам факт ответа TLS-сервера, а не доверие к сертификату.
4. **HTTP-версии** — HTTP/1.1, HTTP/2 и HTTP/3 (QUIC). Если TCP-версии работают,
   а HTTP/3 нет → ограничение UDP/443.
5. **MTU** — маленький (1 КиБ) и большой (256 КиБ) ответ с контролируемого
   endpoint. Маленький проходит, большой зависает → PMTU black hole (часто
   маскируется под «блокировку TLS»).
6. **Traceroute** — на Windows через `IcmpSendEcho` с нарастающим TTL, без прав
   администратора. На других платформах / для IPv6 проверка пропускается.

HTTP/3 в reqwest 0.12 является нестабильной возможностью; в `.cargo/config.toml`
включён флаг `reqwest_unstable`, необходимый для сборки.

## 4. Безопасность

- Приватные адреса (loopback, private, link-local, multicast) отклоняются после
  DNS-разрешения, если `allowPrivateTargets = false`.
- Редиректы на приватные адреса и не-HTTP(S) схемы блокируются.
- Пароль прокси хранится в системном хранилище и не попадает в БД/логи.
- DIRECT-проверки не выдаются за подтверждённые, если egress не совпадает с
  ожидаемым физическим маршрутом.

## 5. Ограничения

- Анализатор не может доказать «вину» конкретного устройства или организации:
  он даёт гипотезу с уровнем уверенности.
- QUIC-тест использует HTTP/3 prior knowledge; some сети/Cdn не поддерживают
  HTTP/3 даже без фильтрации — поэтому требуется повтор и сравнение маршрутов.
- Локализация RU/EN и светлая тема пока не реализованы; интерфейс на русском.
